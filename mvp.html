How to start with Claude Code and build your MVP

Have a business idea but can't code? You can take it from idea to a live link you can send to customers in one afternoon. Here's the exact path I use, with the prompts to copy.

By Nicolás Martelli · 10 min read

Steps at a glance

  1. Write a one-page brief: what problem, for whom, and the one thing the app must do.
  2. Claude Code: describe the idea like you would to a co-founder. It writes the code.
  3. GitHub: ask Claude to save the project there, with every version.
  4. Supabase: your database and user login. It's free to start.
  5. Vercel: publish it and get a link you can share.
  6. Check before sharing: five checks, ten minutes.

0. Before you start: a one-page brief

The biggest time sink isn't code. It's a vague idea. Before opening anything, answer these in a note:

  1. Who is it for? Be specific, for example "freelance bookkeepers in Perth", not "small businesses".
  2. What problem do they have today, and how do they solve it now?
  3. What is the one action your app lets them do? That's your MVP. Everything else waits.
  4. What data needs to be saved: users, clients, invoices…?
  5. How will you know it works? For example: "3 people use it twice in a week."

1. Claude Code: your technical co-founder

Claude Code is Anthropic's AI coding agent. It works inside a folder on your computer: it reads files, writes code, runs commands and shows you the result. It needs a paid Claude plan (Pro or above) or API credits.

Install it by following the official instructions at docs.claude.com. It's one command in the terminal, or you can use the Claude desktop app. Then create an empty folder for your project and open Claude Code there.

Now paste your brief with this prompt:

Prompt · start the project
I want to build an MVP. I'm not a developer, so explain decisions in plain language and keep it simple. Here's my brief: [paste your one-page brief] Please: 1. Ask me any questions you need before starting (one at a time). 2. Propose the simplest stack that works with Supabase for login and data and deploys to Vercel. Use Next.js unless you have a good reason not to. 3. Create a CLAUDE.md file describing the project, the stack and the rules you'll follow. 4. Build only the first screen and show me how to run it locally.

Tip: build in slices

Don't ask for the whole app at once. Ask for one feature, test it in the browser, then ask for the next. Small steps mean fewer bugs and you understand what's happening.

Prompt · add one feature
Next feature: [describe it, e.g. "a user can add a client with name, email and notes, and see the list"]. Build only this. When you're done, tell me exactly how to test it in the browser and what I should see.

2. GitHub: save every version

GitHub stores your code online and keeps every version, so you can always go back. It's also what Vercel publishes from.

  1. Create a free account at github.com.
  2. Create a new private repository, with no README.
  3. Ask Claude to connect and upload:
Prompt · upload to GitHub
Set up git for this project and push it to my GitHub repository: [paste the repo URL]. Before pushing, make sure .env files and any keys or secrets are in .gitignore and never get uploaded. From now on, after each feature works, commit with a short clear message.

3. Supabase: database and login

Supabase gives you a Postgres database, user sign-up and login, and file storage. The free tier is plenty for an MVP.

  1. Create an account at supabase.com and a new project. Save the database password somewhere safe.
  2. Go to Project Settings → API and copy the Project URL and the publishable (anon) key.
  3. Give them to Claude:
Prompt · connect Supabase
Connect the app to Supabase. My Project URL and publishable key are in .env.local (I'll paste them there myself; tell me the exact variable names). 1. Add email sign-up and login. 2. Create the tables we need for [your data] as SQL I can run in the Supabase SQL editor. 3. Turn on Row Level Security so each user can only see and edit their own rows. Explain the policies in plain language. 4. Never use the service_role key in the browser.

Security, in one line

The publishable key is OK in the browser only because Row Level Security decides who sees what. Without RLS, anyone could read your whole database. Always ask Claude to confirm RLS is on.

4. Vercel: publish it

Vercel turns your GitHub repo into a live website, and updates it every time you push.

  1. Sign up at vercel.com with your GitHub account.
  2. Add New → Project, then choose your repository.
  3. In Environment Variables, add the same Supabase URL and key you have in .env.local.
  4. Click Deploy. In a minute or two you get a link like your-app.vercel.app.
  5. In Supabase, go to Authentication → URL Configuration and add your Vercel link, so login emails point to the right place.

Something broke? Copy the error from Vercel and paste it to Claude:

Prompt · fix a deploy error
The Vercel deploy failed with this error: [paste the error] Explain what's wrong in plain language, fix it, and push the fix.

5. Check before you share

Ten minutes now saves an awkward message to your first customer:

  • Sign up with a new email and complete the main action, start to finish, on the live link.
  • Open it on your phone. Does everything fit and work?
  • Log in as a second user: you must not see the first user's data.
  • Search your GitHub repo for "key" and "secret": nothing private should be there.
  • Ask Claude: "Review this app for security problems a beginner would miss."

FAQ

Do I need to know how to code?

No, but you need to be clear about what you want and test every step. You're the product manager; Claude is the engineer.

How much does it cost?

GitHub, Supabase and Vercel all have free tiers that cover an MVP. The main cost is your Claude plan.

What if Claude gets stuck or goes in circles?

Stop, describe what you expected versus what happened, and paste the exact error. If it keeps failing, ask it to undo the last change with git and try a simpler approach.

Can I use my own domain later?

Yes. Buy one and add it in Vercel under Settings → Domains.
